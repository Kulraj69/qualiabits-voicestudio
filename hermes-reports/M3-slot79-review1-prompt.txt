## What the slice claims to be (D1-D8, written before any code)

D1 a per-workspace character ceiling per UTC calendar month and a request rate per API key, both decided *before* the engine is asked, and both set to 'none' for a workspace that never asked for one (a limit nobody asked for is a policy, not a safety net).
D2 the gate is one conditional UPDATE comparing both halves of the month (committed and reserved) in the row it is about to change, so two concurrent requests cannot both take the last of the ceiling — with a thread-race test that fails against the read-then-write version this slice started with, and a second race on the row's own creation.
D3 the ledger stays the record: the counter is a projection seeded from the ledger when it is created (so an upgraded database, or a ceiling set mid-month, counts what was already spent), advanced only beside the usage event it mirrors, and a test asserts the two agree after every kind of request. Reserve/settle/release are three distinct verbs: a cancelled job is released, never charged.
D4 refusals are product behaviour: 402 for the ceiling with the period's reset moment, 429 for the rate with a real Retry-After, the limit numbers in the headers, a machine-readable error code in an object body, and a zero-character row in the meter — because the text never reached the engine.
D5 the honest scope: the ceiling counts characters asked to be spoken, so a transcription is bounded by the rate and not the ceiling; the rate is a fixed window and says so; nothing prunes rate_windows yet; a request that dies mid-flight leaves its reservation standing, and the dashboard shows reserved apart from settled so that difference is visible.
D6 the limits are readable over the API with a key and settable only with a session, and the dashboard's Usage page shows them and sets them; an empty box means no limit rather than a limit of zero; every dashboard error path now reads its message through one function, because refusals became objects and `data.detail` would otherwise have rendered as [object Object] on seven pages.
D7 docs: hosted/M3-ACCEPTANCE.md gains slice G, a table of what the two unbuilt pages (Voice Clone, Voice Design) would need and which engine advertises each, and rows whose evidence is a check in the cited run; DESIGN.md explains the CAS, the two refusal codes and the honest limits; RUN-IT-BY-HAND.md shows a reader how to watch the ceiling hold.

Speech out and speech in are metered separately. `characters` is what a workspace
asked the engine to *say*; `transcript_characters` is what came *back* when it sent
a recording to transcribe; `audio_seconds` is the audio that moved, measured from
the WAV header of the bytes themselves — the returned one for speech, the uploaded
one for transcription. One recording's upload is bounded before it is parsed (25
MiB by default, `QUALI_TRANSCRIBE_MAX_BYTES`), and a refusal never reaches the
engine. Long-form work has no counter of its own on purpose: a project's chapters
are ordinary jobs on the same speech route, so a two-chapter project is two
requests and two chapters' worth of characters, and the assembled audiobook is
not counted as audio that was spoken a second time. A `srt` or `text` answer is not counted in characters, because counting a
subtitle file would count timecodes as speech; its seconds are still recorded.

## How it is built

Each decision below has its reason and its cost in [`hosted/DESIGN.md`](DESIGN.md).
The plane is its own process and database and imports nothing from `backend/`, so an
engine upgrade cannot change how a customer authenticates. Keys are stored as digests
(`qbv_<key_id>_<secret>`; only the id and a SHA-256 digest are kept), so a leak of the
database does not hand over working keys. A job is a row rather than a thread: claiming
is compare-and-swap, a claim is a lease a dying worker stops renewing, and attempts are
bounded — including the last one, which would otherwise sit `running` forever. And the
two counters mean different things on purpose: `characters` is what was asked of the
engine, `audio_seconds` is what arrived, measured from the WAV header of the audio that
came back. Audio is content-addressed — the key *is* the SHA-256 of the bytes — and
writes are read back and verified before they are called stored, on both backends.

## The limits module (hosted/control_plane/limits.py, first 240 lines of 491)

"""Limits that hold: a monthly character ceiling and a per-key request rate.

The plane meters what a customer did. Metering is a record; it is not a brake, and
the difference matters the moment one customer hands a key to a script. This
module is the brake, and it is deliberately small and boring:

**Two limits, two meanings.**

* ``character_ceiling`` — characters this workspace may ask the engine to speak
  in one UTC calendar month. ``0`` means no ceiling, which is the default: a
  limit nobody asked for is not a policy, it is a surprise. The dashboard sets
  it, and the operator may set a house default for new workspaces.
* ``requests_per_minute`` — requests one *API key* may make in a fixed
  one-minute window. Fixed window, not sliding: a client that waits out the
  ``Retry-After`` we send is never refused, but two bursts either side of a
  minute boundary can together total twice the limit. That is stated in the docs
  rather than papered over, because the alternative (a sliding window with a
  per-request timestamp row per key) is a lot of rows to buy a fairness nobody
  has asked for yet.

**Why a reservation and not just a sum.** The ledger is the truth about what was
spent, but reading it and then acting on it is not atomic: two concurrent
requests can both read "12,000 of 12,000 remaining" and both proceed. So a
request *reserves* its characters with a single conditional UPDATE

    UPDATE quota_periods SET reserved = reserved + n
     WHERE id = ? AND committed + reserved + n <= ceiling

and believes only a rowcount of 1 — the same compare-and-swap idiom
``jobs.py`` already uses to claim work, and for the same reason: SQLite has no
``SELECT ... FOR UPDATE``. The reservation is released when the request settles
(its usage event lands in the ledger in the same transaction) or when it is
refused, cancelled or failed, so the two never double-count.

**Both halves live in the counter row, and that is not decoration.** The first
version of this module compared the new reservation against the *ledger* it had
just read, and the thread-race test caught what that costs: a settle commit
between the read and the UPDATE moves spend from ``reserved`` to the ledger, so
the reader's stale ledger figure is too small and it lets the request through.
The gate is now one statement comparing two columns of one row, so the figure it
compares against cannot move underneath it. ``committed_characters`` stays a
projection — the ledger is still the record — but it is seeded from the ledger
when the row is created and advanced only beside the usage event it mirrors.

**What a refusal costs.** Nothing. The text never reached the engine, so the
event is written with zero characters; what it does cost is its rate slot,
because the limiter counts attempts. Both refusal codes say which is which:
``402`` for the ceiling — retrying now cannot help, and the body carries the
moment the period resets — and ``429`` for the rate, with a real
``Retry-After``.

def _period_row(session: Session, workspace_id: int, start: datetime) -> QuotaPeriod:
    """The counter row for one workspace and one period, created if absent.

    The insert races with itself: two requests in the same second on a fresh
    month both find no row. One wins and the other gets an IntegrityError, which
    a savepoint turns into a rollback of *that statement only* — the surrounding
    request transaction keeps going and re-reads the winner's row.

    A new row is seeded with what the ledger already says for this period. That
    matters for a workspace whose ceiling is set for the first time in the middle
    of a month, and for a database upgraded from a slice that had no counters:
    without the seed, its earlier spend would be invisible to the gate and the
    ceiling would be that much larger than the owner asked for.
    """
    def find() -> QuotaPeriod | None:
        return session.execute(
            select(QuotaPeriod).where(
                QuotaPeriod.workspace_id == workspace_id,
                QuotaPeriod.period_start == start,
            )
        ).scalar_one_or_none()

    row = find()
    if row is not None:
        return row
    seeded = settled_characters(session, workspace_id, start)
    try:
        with session.begin_nested():
            row = QuotaPeriod(
                workspace_id=workspace_id,
                period_start=start,
                committed_characters=seeded,
                reserved_characters=0,
            )
            session.add(row)
            session.flush()
        return row
    except IntegrityError:
        row = find()
        if row is None:  # pragma: no cover - the row vanished between two reads
            raise
        return row


def settled_characters(session: Session, workspace_id: int, start: datetime) -> int:
    """Characters this workspace has actually been charged in this period.

    Read straight off the ledger, which is the only place a character is
    counted: a request that was refused before the engine saw it is a row with
    zero characters, so it does not appear here as spend.
    """
    return int(
        session.execute(
            select(func.coalesce(func.sum(UsageEvent.characters), 0)).where(
                UsageEvent.workspace_id == workspace_id,
                UsageEvent.created_at >= start,
            )
        ).scalar_one()
        or 0
    )


def reserved_characters(session: Session, workspace_id: int, start: datetime) -> int:
    row = session.execute(
        select(QuotaPeriod).where(
            QuotaPeriod.workspace_id == workspace_id,
            QuotaPeriod.period_start == start,
        )
    ).scalar_one_or_none()
    return 0 if row is None else int(row.reserved_characters or 0)


def used_characters(session: Session, workspace_id: int, start: datetime) -> int:
    """Spend the ledger records, plus the reservations still standing.

    Read from the ledger rather than from the counter row, because the ledger is
    the record and a number shown to a customer should not be a projection of one.
    :func:`counter_drift` exists so a test can insist the two agree; if they ever
    disagree, the row is what is wrong, not the ledger.
    """
    return settled_characters(session, workspace_id, start) + reserved_characters(
        session, workspace_id, start
    )


def counter_drift(session: Session, workspace_id: int, start: datetime) -> int:

    api_key: ApiKey | None,
    route: str,

) -> NoReturn:
    """Record the refusal the way the meter records everything else, then stop.

    Two decisions worth naming. The event carries **zero** characters: the text
    never reached the engine, and charging the ceiling for a request the ceiling
    itself refused would make the limit inflate its own spend. And the refusal is

        status_code=refusal.status_code,
        characters=0,
        error=refusal.error,
    )
    session.commit()

    # pattern-match English, and the plane's own transcription route already
    # answers with an object detail for the same reason.
    raise HTTPException(
        status_code=refusal.status_code,
        detail=refusal.as_dict(),
        headers=refusal.http_headers(),

"""Bringing the control plane's own database forward, one ordered step at a time.

Slice A refused to start on a database stamped with anything but its own version,
because it had no migration path. That was the right refusal then and the wrong
answer now: slice B adds the queue table, so every slice-A database in existence
(old local runs, and any customer the moment this ships) would have been refused
instead of upgraded. This module is that migration path.

How it works, and why it is this small. The plane owns exactly one schema, applied
linearly; there is no branching and no second consumer, which is the shape
``alembic`` is built for but not the shape we need yet. So the versions live in a
list, each step is a function that receives one transaction, and a database is
stamped with the last version it has actually been brought to, inside the same

stamp alone and the next start retries it, which is why every step must be

turn these functions into a baseline revision; doing it before then would be
paying for machinery this code does not use.

## Where a job settles (hosted/control_plane/jobs.py, first 150 lines)

"""The job queue: claim a job, do the work, settle it once.

Why a queue at all, when slice A already proxies ``POST /v1/audio/speech``. A
paragraph of Hindi on CPU is minutes of compute; an HTTP request is not where that
belongs. A caller needs to hand over the work, get an id back, and come back for
the file — and when the engine is down or the box reboots mid-synthesis, somebody
has to be able to say what happened to that work. That record is the job row.

The hard part is not the table, it is one rule: **exactly one worker does a job**.
Three mechanisms hold that up, and each is tested:

1. Claiming is an optimistic compare-and-swap. The worker selects a candidate id,
   then issues one ``UPDATE ... WHERE id = :candidate AND <still claimable>`` and
   believes only a rowcount of 1. Two workers that read the same candidate both
   write, and the loser's WHERE no longer matches. That works on SQLite, which has
   no ``SELECT ... FOR UPDATE SKIP LOCKED``.
2. A lease, not a lock. A worker that dies holding a job does not hold it forever:
   the claim is valid until ``lease_expires_at``, after which another worker may
   take it. The worker heartbeats while a slow engine call runs, so a live worker
   does not lose a job it is still doing.
3. A bounded number of attempts, and a sweep for the last one. A job whose lease
   expired after its final attempt is not claimable (the claim requires
   ``attempts < max_attempts``) and would sit ``running`` forever, so ``claim_one``
   fails it and writes the one usage event it owes.

One usage event per job, written when the job reaches a terminal state. A retry
after our own failure is not a second order, so the characters are counted once.
The engine time burned on attempts that were thrown away is recorded separately as
``wasted_engine_seconds`` rather than added to ``engine_seconds``, so nobody can
read a blended number as work done for the customer. Cancelling a queued job is
free: nothing was ever sent to the engine, so the meter never sees it.
"""
from __future__ import annotations

from datetime import timedelta
from typing import Any

from sqlalchemy import and_, func, or_, select, update
from sqlalchemy.orm import Session

from . import limits, metering
from .db import ApiKey, Database, Job, utcnow
from .storage import StoredObject

#: Jobs exist for the long text the single-request route refuses; 5,000 is that
#: route's ceiling, so this is deliberately larger and still a stated limit.
MAX_JOB_CHARS = 20000
INPUT_PREVIEW_CHARS = 80

QUEUED = "queued"
RUNNING = "running"
SUCCEEDED = "succeeded"
FAILED = "failed"
CANCELLED = "cancelled"

TERMINAL_STATUSES = (SUCCEEDED, FAILED, CANCELLED)

#: The engine's own refusals are deterministic: asking again changes nothing, so
#: they fail the job on the first try instead of spending two more attempts and
#: two more minutes of CPU to be told the same thing.
RETRYABLE_STATUS_CODES = (502, 503, 504)


def claimable(now) -> Any:
    return or_(
        Job.status == QUEUED,
        and_(
            Job.status == RUNNING,
            Job.lease_expires_at.is_not(None),
            Job.lease_expires_at < now,
        ),
    )


def enqueue(
    session: Session,
    *,
    workspace_id: int,
    api_key_id: int | None,
    text: str,
    voice: str = "",
    response_format: str = "wav",
    max_attempts: int = 3,
) -> Job:
    """Queue one job. The caller validates and commits."""
    job = Job(
        workspace_id=workspace_id,
        api_key_id=api_key_id,
        status=QUEUED,
        input_text=text,
        voice=voice,
        response_format=response_format,
        characters=len(text),
        attempts=0,
        max_attempts=max_attempts,
    )
    session.add(job)
    session.flush()
    return job


def job_dict(job: Job, *, full_input: bool = False) -> dict:
    """What a customer sees. Never another workspace's row, never a worker id."""
    text = job.input_text or ""
    out: dict = {
        "id": job.id,
        "status": job.status,
        "voice": job.voice,
        "response_format": job.response_format,
        "characters": job.characters,
        "attempts": job.attempts,
        "max_attempts": job.max_attempts,
        "created_at": job.created_at.isoformat(),
        "started_at": job.started_at.isoformat() if job.started_at else None,
        "finished_at": job.finished_at.isoformat() if job.finished_at else None,
        "status_code": job.status_code,
        "error": job.error or "",
        "input": text if full_input else text[:INPUT_PREVIEW_CHARS],
        "input_truncated": len(text) > INPUT_PREVIEW_CHARS and not full_input,
        "audio": None,
        "audio_url": None,
    }
    if job.object_key and job.status == SUCCEEDED:
        out["audio"] = {
            "sha256": job.object_sha256,
            "bytes": job.audio_bytes,
            "seconds": job.audio_seconds,
            "engine_seconds": job.engine_seconds,
            "wasted_engine_seconds": job.wasted_engine_seconds,
        }
        out["audio_url"] = f"/v1/jobs/{job.id}/audio"
    return out


def _sweep_unclaimable_running(db: Database, now) -> int:
    """Fail the jobs that are running, out of attempts, and past their lease.

    These are the last attempt of a worker that then died. Nothing else will ever
    claim them (the claim needs an attempt in hand), so leaving them ``running``
    would be a job that is neither going to finish nor going to fail — the worst
    answer for a customer and for anyone reading the log later.
    """
    with db.session() as session:
        rows = session.execute(
            select(Job).where(
                Job.status == RUNNING,
                Job.lease_expires_at.is_not(None),
                Job.lease_expires_at < now,
                Job.attempts >= Job.max_attempts,
            )

## The dashboard's half (lib/quota.js, the limits API route, the panel)

/**
 * The rules for reading and writing a workspace's limits, in one place.
 *
 * Both sides of the dashboard need the same distinction, and getting it wrong is
 * silent: the plane treats an *absent* field as "leave this limit alone" and an
 * explicit `null` as "clear it". A proxy that spreads the request body, or a form
 * that always sends both fields, therefore clears a limit the customer never
 * touched. These two functions are the only places that decision is made, so the
 * Next route and the form cannot disagree about it, and both are unit-tested
 * without a browser or a plane.
 */

/** The two fields a caller may change. Anything else is dropped, not forwarded. */
export const LIMIT_FIELDS = ["character_ceiling", "requests_per_minute"];

/**
 * Rebuild a partial limits change from a request body.
 *
 * Only fields the caller actually sent appear in the result. `null` stays `null`
 * (clear the limit); anything else is coerced to a number so the plane's own
 * validation answers with a schema refusal rather than a string comparison here.
 */
export function limitsPatch(body) {
  const source = body && typeof body === "object" ? body : {};
  const patch = {};
  for (const field of LIMIT_FIELDS) {
    if (!Object.prototype.hasOwnProperty.call(source, field)) continue;
    const value = source[field];
    patch[field] = value === null || value === "" ? null : Number(value);
  }
  return patch;
}

/**
 * The body a limit form submits, and the sentence to show instead when it cannot.
 *
 * An empty box means "no limit" — that is the whole reason this is a function and
 * not two `Number()` calls in a component: `Number("")` is 0, and a ceiling of 0
 * is not no ceiling, it is a ceiling of zero.
 */
export function limitsFormBody({ ceiling, rate }) {
  const body = {};
  for (const [field, raw] of [
    ["character_ceiling", ceiling],
    ["requests_per_minute", rate],
  ]) {
    const text = String(raw ?? "").trim();
    if (text === "") {
      body[field] = null;
      continue;
    }
    if (!/^\d+$/.test(text)) {
      return {
        body: null,
        error: "Both limits are whole numbers: characters per month, and requests per minute.",
      };
    }
    body[field] = Number(text);
  }
  return { body, error: "" };
}

/** What to show for a limit that is set or unset, in the page's own words. */
export function describeLimit(value) {
  return value === null || value === undefined || Number(value) <= 0
    ? "none"
    : String(Number(value));
}

 * body is rebuilt field by field rather than forwarded: the plane distinguishes
 * "absent" from "null" (leave alone versus clear), and a spread would turn a

 * own settled figure, with the reservations still standing shown apart from it —
 * a customer looking at this while a job is running should be able to see why
 * "remaining" is smaller than the ceiling minus what has finished.
 *
 * The form sends only the fields it is asked to change: the plane treats an
 * absent field as "leave alone" and an explicit null as "clear", so pressing
 * Save on one input cannot wipe the other.
 */
export default function LimitsView({ initialLimits }) {
  const [state, setState] = useState(initialLimits || null);
  const [ceiling, setCeiling] = useState(
    initialLimits?.character_ceiling ? String(initialLimits.character_ceiling) : "",
  );
  const [rate, setRate] = useState(
    initialLimits?.requests_per_minute ? String(initialLimits.requests_per_minute) : "",
  );
  const [error, setError] = useState("");
  const [notice, setNotice] = useState("");
  const [busy, setBusy] = useState(false);

  async function send(body) {
    setError("");
    setNotice("");
    setBusy(true);
    try {
      const response = await fetch("/api/limits", {
        method: "PUT",
        headers: { "content-type": "application/json" },
        body: JSON.stringify(body),
      });
      const data = await response.json().catch(() => ({}));
      if (!response.ok) {
        setError(planeDetail(data, "The plane refused the change."));
        return;
      }
      setState(data.limits);
      setNotice(`Changed: ${(data.changed || []).join(", ")}.`);
    } catch {
      setError("The dashboard could not complete the request.");
    } finally {
      setBusy(false);
    }
  }

  function save(event) {
    event.preventDefault();
    const { body, error: problem } = limitsFormBody({ ceiling, rate });
    if (problem) {
      setError(problem);
      return;
    }
    return send(body);
  }

  return (
    <section className="panel" aria-label="Limits" data-testid="limits">
      <div className="panel__head">
        <h2>Limits</h2>
        <p className="panel__note">
          A ceiling on what this workspace may ask the engine to speak in a UTC
          calendar month, and a rate on each API key. They are yours to set;
          nothing here is a bill.
        </p>
      </div>

      <div className="grid grid--stats">
        <div className="stat">
          <p className="stat__label">Character ceiling</p>
          <p className="stat__value" data-testid="limit-ceiling">
            {state?.character_ceiling == null ? "none" : formatCount(state.character_ceiling)}
          </p>
          <p className="stat__note">
            {state?.character_ceiling == null
              ? "no ceiling is set for this workspace"
              : `resets ${formatDateTime(state.period_resets_at)}`}
          </p>
        </div>
        <div className="stat">
          <p className="stat__label">Characters charged</p>
          <p className="stat__value" data-testid="limit-used">{formatCount(state?.characters_settled ?? 0)}</p>
          <p className="stat__note">from the meter, not a second count</p>
        </div>
        <div className="stat">
          <p className="stat__label">Remaining</p>
          <p className="stat__value" data-testid="limit-remaining">
            {state?.character_ceiling == null ? "—" : formatCount(state?.characters_remaining ?? 0)}
          </p>
          <p className="stat__note">
            {(state?.characters_reserved ?? 0) > 0
              ? `${formatCount(state.characters_reserved)} reserved by requests in flight`
              : "nothing reserved by a request in flight"}
          </p>
        </div>
        <div className="stat">
          <p className="stat__label">Rate per key</p>
          <p className="stat__value" data-testid="limit-rate">
            {state?.requests_per_minute == null
              ? "none"
              : `${formatCount(state.requests_per_minute)}/min`}
          </p>
          <p className="stat__note">
            fixed one-minute window; a refused request spends its slot and costs
            no characters
          </p>
        </div>
      </div>

      <form className="form-row" onSubmit={save} data-testid="limits-form">
        <label>
          <span>Character ceiling</span>
          <input
            inputMode="numeric"
            value={ceiling}
            placeholder="none"
            aria-label="Character ceiling"
            onChange={(event) => setCeiling(event.target.value)}
          />
        </label>
        <label>
          <span>Requests per minute, per key</span>
          <input
            inputMode="numeric"
            value={rate}
            placeholder="none"
            aria-label="Requests per minute"
            onChange={(event) => setRate(event.target.value)}
          />
        </label>
        <button type="submit" disabled={busy}>
          {busy ? "Saving…" : "Save limits"}
        </button>
      </form>
      <p className="muted">
        An empty box means no limit. A limit bites the next request; characters
        already charged this month are not unspent by lowering it.
      </p>
      {notice ? <p className="notice">{notice}</p> : null}
      {error ? <p className="notice notice--error">{error}</p> : null}
    </section>
  );
}

# What M3 asked for so far — slices A to E — and where each piece is

No official judging criteria are mapped here, and none can be: M3 is a milestone in
this repository's own plan, not a hackathon this product is entered in. There is no
rules file for it to map against, so this page claims product scope only.

The milestone plan for M3 is: *new web UI (Next.js): clean ElevenLabs-quality
dashboard — Text to Speech, Voice Library, Voice Clone (with consent), Voice Design,
Dubbing, Transcription, Audiobooks/Projects, API Keys, Usage. Responsive, fast,
dark/light.* That is the owner's brief, quoted as it was written, and it is a target
rather than a claim: nothing in this repository measures itself against a commercial
voice product, no such product has been run or quoted, and the two comparisons the
project does have are wall-clock timings against another local engine.

Six slices are built. **Slice A** is the four things a customer does first — sign
up, speak, mint keys, see what was used. **Slice B** is transcription: a recording in,
the engine's transcript out, metered in its own counters. **Slice C** is the Voice
Library: every voice the plane reports, searchable, each one previewable through the
same metered route the Speak page uses, with a hand-off into Speak. Slice C also had
to satisfy the repository's own select rule (`AGENTS.md`, "Shared select controls"):
the five pickers on the site — the voice on Speak and Jobs, the language filter, the
transcription language and answer format, and the library's kind filter — are now one
package-local searchable control instead of native selects, with its pure half tested
without a browser. **Slice D** is long-form: a manuscript in, chapters out. The plane
splits the text at paragraph, then sentence, then word boundaries — never inside a
word — queues one ordinary metered job per chapter, shows per-chapter progress on the
page, and assembles the chapters the engine actually produced into one downloadable
WAV. It refuses in two places rather than guessing: a manuscript whose chapter count
or single word breaks the stated limits, and an assembly whose chapter formats
disagree, because joining 24 kHz mono to 48 kHz stereo produces a file that every
player opens and every listener hears at the wrong speed. **Slice E** is the second
half of the brief's one adjective: the dashboard was dark-only, and it is now dark and
light. Dark is unchanged and stays the default; a reader whose system asks for light,
or who presses the switch in the top bar, gets a light page whose every colour comes
from the same token set, and their choice is remembered. The theme is set on `<html>`
by an inline script the layout renders, before the stylesheet paints, so a remembered
choice never flashes the other one first. A reader whose browser runs no script never
runs that script at all: `<html>` keeps no `data-theme`, and the light palette comes
from the `prefers-color-scheme` fallback in the same stylesheet — driven in a real
browser with script off, and read back over the DevTools protocol because a page with
no script has nothing to ask. That is a readable fallback rather than a working
dashboard without script: a scriptless reader gets the landing page and the sign-in
page, and signing in needs script. Slice E also fixed the hole a judge pass on
slice D pointed at: the home page's card row wraps now, so the seventh tile fills its
row to the edges instead of leaving two columns empty beside it. **Slice F** is
dubbing: a recording in, the engine's own transcript out, and the same words spoken
back in a voice the customer picks, kept as one downloadable WAV. It composes the
plane's two existing engine calls rather than adding an engine capability, so what it
owns is the order that keeps the composition honest — the voice is checked against the
catalogue *before* the recording is read, so a voice the plane would never offer costs
no transcription, and a recording the engine heard no words in is refused rather than
spoken, so an empty dub is impossible. The ear and the mouth stay separate in the
meter: a dub writes one transcription event and one speech event, and the row keeps
each call's own engine seconds apart. It is **not** a translation — there is no
translation model in this repository and none is called — so the dub is in the
language it heard, and the page says so rather than implying otherwise; the engine's
transcript is shown beside the player unedited, because that is what the file will
say. **Slice G** is the limits. A hosted product that meters but cannot stop is one
customer's script away from the month's engine time, so the plane now bounds every
metered request *before* the engine is asked: a character ceiling per workspace per
UTC calendar month, and a request rate per API key in a fixed one-minute window.
Two things make it more than a counter. The gate is one conditional `UPDATE` that
compares both halves of the month — what has been charged and what is reserved by
requests in flight — against the ceiling, because a read-then-write let two
concurrent requests both take the last of it (a thread-race test in
`tests/hosted/test_hosted_limits.py` is what found that, along with a stranded
separator and a cancellation that was charged for work nobody did). And a refusal is
ordinary product behaviour rather than an error page: `402` for the ceiling with the
moment the period resets, `429` for the rate with a real `Retry-After`, a
machine-readable code in the body, the limit and what is left of it in the headers,
and a zero-character row in the meter, because the text never reached the engine. The
ceiling counts characters a customer asks the engine to *speak*: a transcription asks
for none, so it is bounded by the rate and not by the ceiling, and the page says so.
Both limits are readable over the API (`GET /v1/limits`) so a customer can alarm on
the remainder, and settable on the dashboard's own Usage page — with one asymmetry
that is deliberate: a key can *read* the limits, and only a session can change them,
because lowering a client's own ceiling is exactly what a runaway client would do.

Two of the pages
M3 names — Voice Clone with a consent checkbox and Voice Design — are
**not built**, and the last section of this page says so
in the place a reader would otherwise expect a link.

Every row names the code, the tests and a check in the browser run a reader can look
