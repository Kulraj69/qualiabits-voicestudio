# The QualiaBits Voice dashboard

The browser front end for the hosted control plane in [`hosted/`](../). Nine pages,
each one a real thing a customer does: sign up and sign in; speak text and hear it;
browse the engine's own voice catalogue and preview any of them; send a recording in

**Why the page was 560px wide.** The top bar is a flex row, and a flex item's automatic
minimum size is its content's, so a row of items that cannot shrink below their content
cannot be narrower than the sum of those minima either. The bar's minimum came to 560px
and every page inherited it. No amount of padding or wrapping *inside* the page could fix
that, because the offending row was the page's own frame.

**Why the breakpoints are where they are.** Below 900px the bar lays out as two rows — the
brand, the theme switch and the session on the first, the nine nav links on their own
full-width line underneath — because that is the honest way to give nine links room without
either hiding some or letting the row push the session off the page. It used to be decided
at 640px only, and the band between 768 and 900 is the reason it is not any more: a single
row still “fits” there in the arithmetic sense — the bar's one-row minimum is 560px — and
the nav is what pays for it. That band is reasoned from the 560px minimum rather than
measured: the harness drives 390, 768 and 1440, so the tablet end of it is measured and the
rest is an inference this page labels as one. The free space in that row is what the nav
has to live in, so the nav is given its own instead. Below 640px the page padding tightens
once more, the brand's
“Dashboard” suffix goes, so does the signed-in name beside the sign-out button — the home
page's own heading carries it — and the two places with a fixed minimum width — the session
block and the revealed API key — are allowed to shrink. Which of those is *needed* is not a
judgement call: the bar's rows are counted from its own children by the run, and until this
slice's last round that count was published as `undefined`, so a third row at 390px — the
sign-out button pushed onto a line of its own by a name capped at 32vw — was reported as a
pass. With the count fixed the run failed on the real value, the name went, and the phone
bar now measures two rows on all nine pages.

**What the check refuses to call a defect.** A wide table on a phone may scroll inside its
own box: `.table-wrap` is an `overflow-x: auto` container and that is the whole reason it
exists. So the run walks every element on every page and accepts one that overflows *only*
if it sits inside a scroll container that is itself scrollable; anything else is reported
with its tag, class and coordinates. That is also why the assertion is per element and not
per page: `scrollWidth > innerWidth` alone would say a page is broken without saying what
broke it, and the fix would be guesswork.

"""The width rules that make the dashboard responsive have to stay in place.

M3's brief asks for a dashboard that is "responsive, fast, dark/light". The
dark/light half has this file's sibling (`test_theme_tokens.py`) and the light
palette is declared twice so the two copies cannot drift. The *responsive* half
had nothing at all until slice H: `hosted/web/app/globals.css` held exactly one
`@media` rule and it was `prefers-color-scheme` — no width breakpoint anywhere in
983 lines — and the browser harness walked the nine pages at one viewport.

The browser run is the real evidence for the width (it measures what a reader
sees, at three widths, element by element). This file is the cheap guard that
runs without a browser: it parses the stylesheet and fails if the breakpoints
that the run depends on are removed, reordered, or made to break the promise the
theme half relies on — that a width rule never re-colours anything, because a
token declared for one theme has to be declared for the other.
"""
from __future__ import annotations

import hashlib
import re
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parents[2]
WEB = REPO_ROOT / "hosted" / "web"
CSS = WEB / "app" / "globals.css"
HARNESS = WEB / "e2e" / "dashboard.mjs"

COMMENT_RE = re.compile(r"/\*.*?\*/", re.DOTALL)
MEDIA_RE = re.compile(r"@media[^{]*\{")
MEDIA_WIDTH_RE = re.compile(r"@media\s*\(\s*max-width:\s*(\d+)px\s*\)")
DECL_RE = re.compile(r"(--[a-z0-9-]+)\s*:\s*([^;{}]+);")
#: The widths the browser suite drives, in the order it drives them.
VIEWPORTS = ((390, 844), (768, 1024), (1440, 900))
#: The stylesheet as it stood before slice H, copied out of
#: `git show bd6c51bba:hosted/web/app/globals.css` so the desktop guard below needs
#: neither git nor the network. The sha256 is of the file as committed here; the
#: pinned value was read back out of that command's output, not typed from memory.
BEFORE_SLICE_H = Path(__file__).resolve().parent / "fixtures" / "globals-before-slice-h.css"
BEFORE_SLICE_H_SHA256 = "c930ab80f56d104056355a92378c60e3e6b72a091451c47c036382add117ebf2"
BEFORE_SLICE_H_REVISION = "bd6c51bba"


def strip_comments(text: str) -> str:
    return COMMENT_RE.sub("", text)


def css() -> str:
    return strip_comments(CSS.read_text(encoding="utf-8"))


def strip_width_blocks(source: str) -> str:
    """`source` with every top-level `@media {...}` block taken out.

    A window wider than the blocks' widths never matches them, so what is left is
    the set of rules a desktop reader gets. Comments are expected to be stripped by
    the caller; this only removes whole blocks, brace-matched, so a nested rule does
    not end one early.
    """
    out: list[str] = []
    index = 0
    while index < len(source):
        match = MEDIA_RE.search(source, index)
        if not match:
            out.append(source[index:])
            break
        out.append(source[index : match.start()])
        depth = 1
        cursor = match.end()
        while cursor < len(source) and depth:
            if source[cursor] == "{":
                depth += 1
            elif source[cursor] == "}":
                depth -= 1
            cursor += 1
        index = cursor
    return "".join(out)


def rules_only(source: str) -> list[str]:
    """The width-blocked removal of `source` as a list of rules, one per line.

    Comments, blank lines and trailing spaces are not rules: an editor may space the
    stylesheet out differently without changing what a desktop reader gets, and this
    guard is about what they get.
    """
    return [
        line.rstrip()
        for line in strip_width_blocks(strip_comments(source)).splitlines()
        if line.strip()
    ]


def first_line_difference(before: list[str], after: list[str]) -> str:
    """A sentence naming the first rule that differs, for the failure message."""
    for index, (left, right) in enumerate(zip(before, after)):
        if left != right:
            return (
                f"line {index + 1} of the rules reads {left!r} where "
                f"{BEFORE_SLICE_H_REVISION} had {right!r}"
            )
    if len(before) != len(after):
        extra = before[len(after) :] or after[len(before) :]
        return (
            f"the rule list changed length, {len(before)} -> {len(after)} lines; "
            f"the first line without a counterpart is {extra[0]!r}"
        )
    return "the two rule lists compare equal (this should not be reported)"


def block_after(text: str, marker: str) -> str:
    """The body of the first `{...}` block whose text starts at `marker`."""
    start = text.index(marker)
    open_brace = text.index("{", start)
    depth = 0
    for i in range(open_brace, len(text)):
        if text[i] == "{":
            depth += 1
        elif text[i] == "}":
            depth -= 1
            if depth == 0:
                return text[open_brace + 1 : i]
    raise AssertionError(f"unbalanced braces after {marker!r}")


def width_blocks_in(source: str) -> list[tuple[int, str]]:
    """Every `@media (max-width: Npx)` block in `source`, in file order."""
    out = []
    for match in MEDIA_WIDTH_RE.finditer(source):
        out.append((int(match.group(1)), block_after(source, match.group(0))))
    return out


def width_blocks() -> list[tuple[int, str]]:
    """The same, for the stylesheet as it stands now."""
    return width_blocks_in(css())


def block_in(text: str, marker: str) -> str:
    """`block_after`, but a missing selector is a sentence, not a traceback.

    A rule that has been deleted is the failure this file is looking for, and it
    should read as one: `ValueError: substring not found` names neither the rule
    nor the width block it was in.
    """
    assert marker in text, f"this width block no longer contains {marker!r}"
    return block_after(text, marker)


def declarations(block: str) -> dict[str, str]:
    return {name: " ".join(value.split()) for name, value in DECL_RE.findall(block)}

# What M3 asked for so far — slices A to H — and where each piece is

No official judging criteria are mapped here, and none can be: M3 is a milestone in
this repository's own plan, not a hackathon this product is entered in. There is no
rules file for it to map against, so this page claims product scope only.

The milestone plan for M3 is: *new web UI (Next.js): clean ElevenLabs-quality
dashboard — Text to Speech, Voice Library, Voice Clone (with consent), Voice Design,
Dubbing, Transcription, Audiobooks/Projects, API Keys, Usage. Responsive, fast,
dark/light.* That is the owner's brief, quoted as it was written, and it is a target
rather than a claim: nothing in this repository measures itself against a commercial
voice product, no such product has been run or quoted, and the two comparisons the
project does have are wall-clock timings against another local engine.

Eight slices are built. **Slice A** is the four things a customer does first — sign
up, speak, mint keys, see what was used. **Slice B** is transcription: a recording in,
the engine's transcript out, metered in its own counters. **Slice C** is the Voice
Library: every voice the plane reports, searchable, each one previewable through the
same metered route the Speak page uses, with a hand-off into Speak. Slice C also had
to satisfy the repository's own select rule (`AGENTS.md`, "Shared select controls"):
--- lines 58-120 ---
say. **Slice G** is the limits. A hosted product that meters but cannot stop is one
customer's script away from the month's engine time, so the plane now bounds every
metered request *before* the engine is asked: a character ceiling per workspace per
UTC calendar month, and a request rate per API key in a fixed one-minute window.
Two things make it more than a counter. The gate is one conditional `UPDATE` that
compares both halves of the month — what has been charged and what is reserved by
requests in flight — against the ceiling, because a read-then-write let two
concurrent requests both take the last of it (a thread-race test in
`tests/hosted/test_hosted_limits.py` is what found that, along with a stranded
separator and a cancellation that was charged for work nobody did). And a refusal is
ordinary product behaviour rather than an error page: `402` for the ceiling with the
moment the period resets, `429` for the rate with a real `Retry-After`, a
machine-readable code in the body, the limit and what is left of it in the headers,
and a zero-character row in the meter, because the text never reached the engine. The
ceiling counts characters a customer asks the engine to *speak*: a transcription asks
for none, so it is bounded by the rate and not by the ceiling, and the page says so.
Both limits are readable over the API (`GET /v1/limits`) so a customer can alarm on
the remainder, and settable on the dashboard's own Usage page — with one asymmetry
that is deliberate: a key can *read* the limits, and only a session can change them,
because lowering a client's own ceiling is exactly what a runaway client would do.
**Slice H** is the second adjective in that brief: *responsive*. Until it, the
stylesheet held exactly one width-free `@media` rule — the light palette's
`prefers-color-scheme` fallback — and no breakpoint anywhere, so a customer who opened
the dashboard on a phone got the desktop layout squeezed, and no run in this repository
had ever looked. It has two widths now (900px and 640px), and they are layout only: a
breakpoint may move a box, never re-colour one, because a colour token declared inside a
width block would be a third copy of the palette that the theme guard knows nothing
about. The measured claim is not "it looks fine" but what a real browser reports on all
nine pages at 390x844, 768x1024 and 1440x900: no page scrolls sideways, no element is
wider than the window, the heading stays inside it, and — at the two narrow widths — the
top bar's own controls stay inside the window and stay big enough to press. Two
defects are on the record in that harness rather than quietly fixed: the bar whose flex
children could not shrink below their content (the document measured 560px wide in a
390px window, so the session block sat off the right edge), and the page padding and the
session control, which had to be allowed to shrink once more below 640px. Those before-numbers
are one run's own output — `hermes-reports/M3-slot81-web-e2e-before-r1.log`, kept as the
transcript it is because that run was taken over a working tree and no `result.json` for it
